# API мессенджера

Описание HTTP-контракта сервера. Машиночитаемая версия — OpenAPI-документ,
он генерируется из кода и доступен по адресу `GET /openapi/v1.json`
(во всех средах).

## Формат ошибок

Все ошибки возвращаются в формате RFC 9457 (`application/problem+json`):

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.5",
  "title": "Диалог не найден",
  "status": 404,
  "detail": "Диалог не найден.",
  "code": "dialog_not_found"
}
```

Поле `code` — стабильный машинно-читаемый код: фронтенд ориентируется на
него, а не на текст. Тексты (`title`, `detail`) — на русском и могут
меняться. При ошибке валидации дополнительно приходит объект `errors`:
имя поля → список сообщений.

### Коды ошибок

| Код                      | HTTP | Когда                                                          |
|--------------------------|------|----------------------------------------------------------------|
| `validation_failed`      | 400  | Тело запроса не прошло проверку полей.                         |
| `unauthorized`           | 401  | Сессия отсутствует или закончилась.                            |
| `invalid_credentials`    | 401  | Неверный публичный ID или пароль.                              |
| `user_not_found`         | 404  | Пользователь с указанным публичным ID не найден.               |
| `dialog_not_found`       | 404  | Диалог не найден **или** пользователь в нём не участвует.      |
| `attachment_not_found`   | 404  | Вложение не найдено **или** у пользователя нет к нему доступа. |
| `not_found`              | 404  | Неизвестный адрес API.                                         |
| `method_not_allowed`     | 405  | Для адреса не поддерживается такой метод.                      |
| `forbidden`              | 403  | Недостаточно прав для действия.                                |
| `unsupported_media_type` | 415  | Ожидался запрос в формате JSON.                                |
| `duplicate_dialog`       | 409  | Диалог между этой парой участников уже существует.             |
| `duplicate_public_id`    | 409  | Публичный ID уже занят другим пользователем.                   |
| `duplicate_attachment`   | 409  | Вложение с таким идентификатором уже загружено.                |
| `message_conflict`       | 409  | Повтор отправки от другого отправителя или с изменённым пакетом под тем же ID. |
| `attachment_too_large`   | 413  | Файл больше 25 МБ.                                             |
| `rate_limited`           | 429  | Превышен лимит запросов к auth-методам; повторите позже.       |
| `internal_error`         | 500  | Внутренняя ошибка сервера. Подробности — только в логах.       |

## Авторизация

Сессия выдаётся при входе и передаётся в cookie `messenger_session`
(`HttpOnly`, `Secure`, `SameSite`). Методы, требующие сессии, помечены в
спецификации схемой `sessionCookie`.

Выход отзывает сессию на сервере и удаляет cookie.

## Правила вложений

- Сервер не получает и не хранит исходное имя файла и открытое содержимое.
  Имя файла и тип содержимого клиент шифрует сам и приходит они как
  `encryptedMetadata`.
- Вложение принадлежит копии сообщения: метаданные видны только владельцу
  этой копии.
- У сообщения две копии — по одной на участника. Вложение заводится в
  каждой копии и ссылается на одни и те же зашифрованные байты: у получателя
  свой просмотр, удаление «у себя» трогает только его копию.
- Идентификаторы сообщения и вложения задаёт клиент: сервер их не
  генерирует, чтобы обе стороны одинаково собрали AAD шифрования
  метаданных. Идентификатор вложения уникален в пределах копии сообщения,
  идентификатор сообщения — в пределах диалога. В AAD входят вместе
  идентификатор диалога, сообщения и вложения, поэтому вложение нельзя
  перенести в другое сообщение того же диалога.
- Максимальный размер одного вложения — 25 МБ.
- MIME, присланный клиентом, не считается доверенным: сервер не смотрит
  на тип содержимого и не сохраняет имя файла. Тело запроса — только
  зашифрованные байты.

## Методы

### Сообщения

Детальный протокол сообщений, доставки и восстановления клиента описан в
[messaging.md](messaging.md). Кратко:

- `POST /dialogs/{dialogId}/messages` — отправка криптопакета
  `{v, id, sentAt, iv, ct}`. Новое сообщение — `201`, идемпотентный
  повтор или отправка уже удалённого сообщения — `200` с флагом
  `deleted=true`, конфликт — `409 message_conflict`. Требует сессии.
- `GET /dialogs/{dialogId}/messages?limit=50&before=<cursor>` (алиас
  `beforeId`) — история своей копии, keyset-пагинация, до 100 на страницу.
- `POST /dialogs/{dialogId}/messages/sync` — до 500 ID, ответ
  `{missingIds, revision}` — сверка удалённого.
- `DELETE /dialogs/{dialogId}/messages/{messageId}?forEveryone=true|false`
  — удаление своей копии или обеих; повтор возвращает `204`.
- `POST /dialogs/{dialogId}/messages/delete-self` — удаление выбранных
  своих копий; `{}` очищает всю личную историю.
- `POST /dialogs/{dialogId}/messages/delete-both` — атомарное удаление
  выбранных копий у обоих участников.

### `POST /auth/register`

Регистрация аккаунта. Телефон и email не требуются: сервер выдаёт
публичный ID.

Тело: `{ "password": "..." }` — не короче 8 символов.

Ответ `201`: `{ "publicId": "..." }`.

Ошибки: `validation_failed` (400), `duplicate_public_id` (409).

### `POST /auth/login`

Вход по публичному ID и паролю. Устанавливает cookie-сессию.

Тело: `{ "publicId": "...", "password": "..." }`.

Ответ `200`: `{ "publicId": "..." }`.

Ошибки: `validation_failed` (400), `invalid_credentials` (401).

### `POST /auth/logout`

Отзывает сессию на сервере и удаляет cookie. Ответ `204`.

### `GET /auth/me`

Текущий пользователь. Требует сессии.

Ответ `200`: `{ "publicId": "...", "createdAt": "..." }`.

Ошибки: `unauthorized` (401).

### `GET /users/by-id/{id}`

Точный поиск пользователя по публичному ID. Частичное совпадение не
даёт результата. Требует сессии.

Ответ `200`: `{ "publicId": "...", "createdAt": "..." }`.

Ошибки: `unauthorized` (401), `user_not_found` (404).

### `POST /dialogs`

Создаёт диалог один-на-один. Если такой диалог уже есть, возвращает
его — дубль не создаётся. Требует сессии.

Тело: `{ "publicId": "..." }` — публичный ID собеседника.

Ответ `201` (создан) или `200` (уже был): `{ "id": "...", "companionPublicId": "...", "createdAt": "..." }`.

Ошибки: `validation_failed` (400), `unauthorized` (401), `user_not_found` (404).

### `GET /dialogs`

Список диалогов пользователя. Диалоги, в которых пользователь не
участвует, не показываются. Требует сессии.

Ответ `200`: массив `{ "id": "...", "companionPublicId": "...", "createdAt": "...", "label": {...} | null }`.
Поле `label` — подпись контакта текущего пользователя, собеседнику она не видна.

Ошибки: `unauthorized` (401).

### `GET /dialogs/{id}`

Открытие диалога. Доступно только участникам: постороннему диалог по
идентификатору не раскрывается — ответ тот же, что и для несуществующего
диалога (`404`). Требует сессии.

Ответ `200`: `{ "id": "...", "companionPublicId": "...", "createdAt": "...", "label": {...} | null }`.

Ошибки: `unauthorized` (401), `dialog_not_found` (404).

### `PUT /dialogs/{dialogId}/label`

Сохраняет подпись контакта текущего пользователя. Тело — зашифрованный
ключом диалога пакет `{ "v": 1, "iv": "...", "ct": "..." }` (base64url);
сервер его не расшифровывает. Повторный вызов заменяет подпись.
Требует сессии.

Ответ `204`.

Ошибки: `validation_failed` (400 — неверный формат или размер: `iv` ровно
12 байт, `ct` от 16 до 512 байт), `unauthorized` (401), `dialog_not_found` (404).

### `DELETE /dialogs/{dialogId}/label`

Удаляет подпись контакта текущего пользователя. Идемпотентно: отсутствие
подписи ошибкой не считается. Требует сессии.

Ответ `204`.

Ошибки: `unauthorized` (401), `dialog_not_found` (404).

### `POST /dialogs/{dialogId}/messages/{clientMessageId}/attachments/{clientAttachmentId}`

Отправитель загружает зашифрованные байты один раз. Сервер привязывает их к существующим копиям исходного сообщения. Требуется сессия отправителя.

Тело запроса — сами зашифрованные байты (любой `Content-Type` допустим:
MIME клиента не доверенный и сервер его не использует). Зашифрованные
клиентом метаданные (имя файла, тип содержимого) передаются в обязательном
заголовке `X-Attachment-Metadata` в base64; их размер ограничен 16 КБ.

Ответ `201` — метаданные вложения, как у `GET` одного вложения.

- Размер больше 25 МБ отклоняется с кодом `attachment_too_large` (413) и
  понятным сообщением; файл при этом не сохраняется.
- Пустое тело — `validation_failed` (400).
- Загрузка в чужую копию сообщения — `attachment_not_found` (404): то же,
  что и для несуществующего вложения.
- Повторная загрузка того же `clientAttachmentId` — `duplicate_attachment`
  (409); проверка идёт до записи байтов, диск зря не занимается.

### `GET /dialogs/{dialogId}/messages/{clientMessageId}/attachments/{clientAttachmentId}`

Метаданные зашифрованного вложения. Доступно только владельцу копии
сообщения, к которому вложение относится: постороннему вложение не
раскрывается — ответ тот же, что и для несуществующего (`404`). Требует
сессии.

Ответ `200`:

```json
{
  "clientMessageId": "...",
  "clientAttachmentId": "...",
  "size": 1024,
  "uploadedAt": "2026-11-16T10:00:00Z",
  "encryptedMetadata": "7s2XQhE="
}
```

`clientMessageId` — поле `id` из пакета сообщения `{v, id, sentAt, iv, ct}`,
`clientAttachmentId` задаёт клиент при загрузке вложения. Оба идентификатора
одинаковы у копий сообщения у обоих участников, поэтому по ним обе стороны
собирают AAD шифрования метаданных одинаково. В AAD входят вместе
идентификатор диалога, сообщения и вложения.

`encryptedMetadata` — зашифрованные клиентом имя файла и тип содержимого.
Формат пакета — такой же, как у сообщения: `{v, id, sentAt, iv, ct}`,
где `ct` — AES-256-GCM с проверяемым тегом. Передаётся как base64,
расшифровывает только клиент. Сервер не знает и не хранит исходное имя
файла и открытое содержимое.

Максимальный размер одного вложения — 25 МБ (`25000000` байт). Это значение
задано один раз в коде (`MediaLimits.MaxAttachmentSizeBytes`), чтобы
фронтенд не расходился с сервером в трактовке лимита.

Ошибки: `unauthorized` (401), `attachment_not_found` (404).

### `GET /dialogs/{dialogId}/messages/{clientMessageId}/attachments/{clientAttachmentId}/content`

Скачивание зашифрованных байтов вложения из своей копии сообщения.
Доступно только владельцу копии: постороннему — тот же ответ, что для
несуществующего вложения (`404`). Требует сессии.

Ответ `200`: тело — сами зашифрованные байты, как их прислал владелец при
загрузке. Расшифровка выполняется на клиенте ключом диалога; сервер не
знает и не хранит тип содержимого, поэтому отдаёт `application/octet-stream`
и не выставляет имя файла. Ответ помечен `Cache-Control: no-store`.

Ошибки: `unauthorized` (401), `attachment_not_found` (404).

### `GET /dialogs/{dialogId}/messages/{clientMessageId}/attachments`

Метаданные всех вложений копии сообщения. Список нужен клиенту, чтобы
узнать о вложениях: сообщение зашифровано целиком, поэтому идентификаторы
вложений он иначе не увидит.

Ответ `200`: массив объектов, как у запроса одного вложения.

Чужие копии сообщения не видны: для них возвращается пустой список.

Ошибки: `unauthorized` (401).

### `GET /health`

Проверка живости сервиса. Ответ `200`: `{ "status": "ok" }`.
