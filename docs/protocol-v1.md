# Клиентская криптография v1

AES-256-GCM: случайный ключ 32 байта на диалог, IV 12 случайных байт на каждое
шифрование, тег 128 бит. Серверу передаются только ciphertext и метаданные
пакета. Ключи генерируются/передаются вручную/хранятся на клиенте.

Для совместимых новых клиентов фиксируем AAD как UTF-8 без BOM от JSON-массива
без пробелов:

```js
const aad = new TextEncoder().encode(JSON.stringify([
  1,
  dialogId.toLowerCase(),
  senderId.toLowerCase(),
  id.toLowerCase(),
  new Date(sentAt).toISOString()
]));
```

UUID — стандартная форма с дефисами в нижнем регистре. Время — UTC с тремя
цифрами миллисекунд и `Z`; та же нормализация обязательна при расшифровании,
даже если JSON serializer REST вернул `+00:00`. SenderId — UUID `id` из
`/auth/me`, не публичный читаемый ID. Сервер подставляет его из сессии, поэтому
клиенту следует узнать свой ID до шифрования.

`ct` = ciphertext с 16 байтами тега в конце; `iv` и `ct` — стандартный base64.
Сначала проверить тег, затем показывать plaintext. При неверном ключе или
изменении AAD/ct клиент сообщает об ошибке, не показывает непроверенные байты.
Дедупликация по ID нужна отдельно от AEAD.

[Публичный тестовый вектор](protocol-v1-vector.json) содержит заведомо тестовые
ключ/IV, plaintext, точную строку AAD и ожидаемый ct. Он проверен через Node
WebCrypto: roundtrip успешен, изменение ct, sentAt или id отвергается.
Фиксированные ключ/IV из вектора не применяются в реальных сообщениях.

Backend не реализует WebCrypto/IndexedDB, ручной Base32-обмен ключами или
очистку памяти браузера. Этот документ фиксирует формат для фронтенда и
будущих Avalonia-клиентов. Изменение сериализации AAD требует новой версии
протокола и согласованного обновления клиентов.
